## 1. 修正後のテストにおける「5枚目の牌」問題

最新の [test_v2_core.py](file:///c:/Users/Daikichi/Documents/code-workspace/雀魂コーチングくん/ver2/tests/test_v2_core.py) の `test_genbutsu_is_safe` では、テストを合格させるために以下のようなデータ設定が行われています。

```python
def test_genbutsu_is_safe(self):
    # 9m を手牌に含めて、誰かが切った牌 → 現物
    state = make_state(
        hand=['1m', ..., '9m'],                  # ① 自分自身が手牌に 9m を 1 枚持っている (my_count = 1)
        reach_states=[False, True, False, False],
    )
    state.river[1] = ['9m', '9m', '9m', '9m']    # ② リーチ者の河に 9m が 4 枚切られている (public_count = 4)
    score = safety_score(state, '9m')
```

### 🔴 論理的な矛盾点
1. **世界に5枚存在する牌**: 麻雀牌は各種類 4 枚しかありません。自分が手牌に 1 枚持っている（①）のに、河に 4 枚すべて切られている（②）というのは、**世界に `9m` が 5 枚存在している不可能なゲーム状態**をシミュレートしています。
2. **なぜこのテストが通るのか？**: 
   安全度計算の条件式 `public_count >= 4 - my_count` に、上記の「5枚目の牌」を代入すると、`4 >= 4 - 1`（`4 >= 3`）となり、条件が `True` になるため、安全度 `1000` を返してテストがパスします。
3. **ご指摘の通り**: もし麻雀のルール通り、河に4枚すべて切られている（`public_count = 4`）なら、自分は手牌に持てないため `my_count = 0` になるはずです。手元にない牌は打牌選択の対象にならないため、そもそも安全度計算を呼び出す必要自体がありません。

## 2. 根本的な原因：「現物」と「ノーチャンス」の混同

この論理矛盾は、[defense_v2.py](file:///c:/Users/Daikichi/Documents/code-workspace/雀魂コーチングくん/core/defense_v2.py) において**「現物（フリテン現物）」と「ノーチャンス（4枚見え）」を一つの条件式で雑に判定しようとしていること**が原因です。

```python
# === 現物 (絶対安全) ===
if public_count >= 4 - my_count:
    return 1000
```
このコードは、コメントでは「現物」と書いてありますが、実際には「4枚見え（ノーチャンス）」を判定しています。

### 💡 本来あるべき論理設計（2つの絶対安全）
他家がロンできない「絶対安全（1000）」には、以下の2通りを明確に区別して判定する必要があります。

1. **フリテン現物（本当の現物）**:
   - 条件: **その牌が、リーチ者の河にある**。
   - 特徴: 自分がその牌を何枚持っていようが（0枚でも1枚でも）、相手の河にあればロンされない（同巡フリテン含む）。
2. **ノーチャンス（4枚見え）**:
   - 条件: **自分から見えている合計枚数（手牌＋場）が 4 枚である**。
   - 特徴: 自分以外の誰もその牌を持っていない（持てない）ため、相手は単騎待ち・双碰待ち・両面などのすべての待ちにその牌を指定できず、絶対にロンされない。

## 3. 推奨される安全度判定の修正イメージ

コードの修正作業は行いませんが、設計としてあるべき `safety_score` の論理構造は以下のようになります。

```python
def safety_score(state, tile: str) -> int:
    tile_id = tile_to_id(tile)
    visible = state.all_visible_counts()
    
    # -------------------------------------------------------------
    # 1. ノーチャンス (自分から見て 4 枚すべて見えている)
    #    自分が 1 枚持っていて他で 3 枚見えている、もしくは自分が 2 枚持っていて他で 2 枚見えている等の場合。
    #    (※自分が 0 枚持っていて他で 4 枚見えている牌は、手牌にないのでこの関数には渡されない)
    # -------------------------------------------------------------
    if visible[tile_id] >= 4:
        return 1000

    # -------------------------------------------------------------
    # 2. リーチ者の現物 (フリテン現物)
    #    リーチしている他家全員の河にその牌があるか確認
    # -------------------------------------------------------------
    reach_seats = [s for s in range(4) if s != state.my_seat and state.reach_states[s].is_reach]
    if reach_seats:
        is_genbutsu_all = True
        for seat in reach_seats:
            # リーチ者の河にあるか判定
            river_ids = [tile_to_id(t) for t in state.river[seat]]
            if tile_id not in river_ids:
                is_genbutsu_all = False
                break
        if is_genbutsu_all:
            return 1000  # 全員の現物なら 1000 (絶対安全)

    # -------------------------------------------------------------
    # 3. それ以外の危険度評価 (リーチありなら待ち重み、なしならスジ等)
    # -------------------------------------------------------------
    ...
```

このように判定を整理することで、「世界に5枚ある状態」を作らなくても、**「手牌にある 9m (1枚) ＋ リーチ者の河にある 9m (1枚以上)」という正常な麻雀のルール範囲内で、現物テスト（安全度 1000）を綺麗にパスさせることができます。**
