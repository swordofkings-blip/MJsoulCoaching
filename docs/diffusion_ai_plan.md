# 拡散モデル応用AI「diff-I」実装計画

## 概要

画像生成AIの拡散モデル（Denoising Diffusion Probabilistic Models）のアルゴリズムを麻雀AIに応用する。

**コアアイデア**: 麻雀の「不確定な未来（山牌）」をノイズと見なし、観測情報（手牌・河・副露）を条件として「最適な着手」を逆拡散過程で求める。

```
初期ノイズ（山牌ランダム性）
  ↓ 条件（手牌, 河, 順位目標, 他家行動）
  ↓ 逆拡散（段階的ノイズ除去）
最適行動分布（打牌確率・リーチ判断 etc.）
```

## 全体アーキテクチャ（提案）

```
                    ┌──────────────────┐
                    │  棋譜データセット  │
                    │ (天鳳/雀魂)       │
                    └───────┬──────────┘
                            ↓
                    ┌──────────────────┐
                    │  特徴量エンコーダ  │ ← 教師ラベル（打牌/リーチ）
                    └───────┬──────────┘
                            ↓
                   ┌────────────────────┐
                   │ 拡散モデル (D3PM)   │
                   │ 打牌分布を逆拡散生成  │
                   │ (34次元 logits)     │
                   └────────┬───────────┘
                            ↓ 提案行動
                   ┌────────────────────┐
              ┌───→│ coach-I 検証器     │ ← ルールベースで妥当性チェック
              │    │ (Rejection Sampler)│    (現物スジ壁, ファジィ戦略 etc.)
              │    └────────┬───────────┘
              │             ↓ OK
              │    ┌────────────────────┐
              │    │ 最終アクション出力  │
              │    │ 打牌/リーチ/鳴き    │
              │    └────────────────────┘
              │             ↑ NG（ルール違反/低スコア）
              └─────────────┘
              ループ (再サンプリング)
```

**検証器の役割**:
- 拡散モデルの提案が明らかな悪手（牌の重複、ルール違反など）を**ハードリジェクト**
- coach-I の評価スコアが閾値を下回る提案を**ソフトリジェクト**
- リジェクト後はノイズを再注入して逆拡散をやり直す or 別サンプルを生成

これにより「NNの柔軟性 + ルールAIの安全性」を両立する。

## フェーズ1: 教師あり学習ベースライン（軽量Policy Net）

**目標**: 拡散モデル導入前に、通常の教師あり学習でベースラインを確立する。ここでの成果が拡散モデルの比較対象となる。

- [ ] `core/nn_policy.py` — 軽量アーキテクチャ
  - 入力: 局面テンソル (≈ 500-1000次元)
  - 出力: 打牌確率分布 (34次元) + リーチ確率 (1次元)
  - アーキテクチャ: MLP (2-3層) or 小型Transformer
  - パラメータ数: ~10万（coach-Iのルールパラメータと同程度）
- [ ] `tools/train_supervised.py` — 学習スクリプト
  - 損失関数: CrossEntropy (打牌) + BinaryCrossEntropy (リーチ)
  - 最適化: AdamW, CosineAnnealing
  - データ: 訓練8:検証1:テスト1
- [ ] 評価: 打牌一致率（top-1 / top-3）, リーチ判断正解率
- [ ] coach-I とのハイブリッド統合試験
  - `total_score[tile] = coach_I_score[tile] + w * nn_logit[tile]`
  - 重み`w`をvalidationで調整

**成功基準**: 打牌一致率がcoach-I単体を上回る

## フェーズ2: 離散拡散モデル（Discard Diffusion Policy）

**目標**: 打牌決定を「34次元カテゴリカル分布の拡散過程」としてモデル化する。画像のピクセル段階的生成と同じ枠組みで打牌を「段階的に絞り込む」。

**理論**: 標準DDPMは連続値用。麻雀の打牌 (34クラス分類) には **D3PM (Discrete Denoising Diffusion Probabilistic Models, Austin et al. 2021)** または **Multinomial Diffusion (Hoogeboom et al. 2021)** を用いる。

- [ ] `core/diffusion_policy.py` — 拡散カーネル
  - 前方過程: ユニフォームノイズへのマスキング/遷移 (34×34遷移行列)
  - 逆拡散: 条件付きノイズ除去ネットワーク `ε_θ(state, noisy_logits, t)`
  - タイムステップ t: 0 (確定) → T (完全ノイズ)
- [ ] `core/noise_scheduler.py` — ノイズスケジュール
  - 線形 / cosine / カスタムスケジュール
- [ ] `tools/train_diffusion.py` — 学習
  - 損失: variational lower bound on the negative log-likelihood
  - サンプリング: DDPM reverse process (T step) または DDIM (高速)
- [ ] 評価: フェーズ1のPolicy Netと一致率比較

**キーコンセプト（麻雀における解釈）**:

| 画像生成 | 麻雀適用 |
|---|---|
| ピクセル位置 | 34種牌 |
| RGB値 | 打牌確率 (softmax logits) |
| ノイズ付加 | 手牌信息の不明確さを模擬 |
| プロンプト(Text) | 局面条件 (手牌,河,点数状況) |
| ネガティブプロンプト | 4位回避 / 放銃回避条件 |
| サンプリングステップ | 打牌の段階的絞り込み |

**実装オプション: Rejection Sampling Loop**

拡散モデルの出力をcoach-I検証器でフィルタする2段構成：

```python
def decide(state, max_attempts=5):
    for _ in range(max_attempts):
        noisy_logits = sample_gaussian_noise(...)
        for t in reversed(range(T)):
            eps = denoise_model(noisy_logits, state, t)
            noisy_logits = remove_noise(noisy_logits, eps, t)
        action = argmax(noisy_logits)

        # coach-I検証
        score = coach_I.evaluate_action(state, action)
        if score >= REJECT_THRESHOLD:
            return action

    # 全てリジェクト → coach-Iの最善手にフォールバック
    return coach_I.best_discard(state)
```

**利点**: 拡散モデルがルールを学習しきれていなくても、coach-Iが最終防衛線になる。

**検証器の進化パス**:

```
初期 (Phase 2):
  REJECT = coach_score < threshold
  → coach-Iに従わせる。拡散モデルの暴走を防ぐ。

中期 (Phase 3-4):
  REJECT = coach_score < threshold * α  (α: 0.8 → 0.5 → 0.2 と減衰)
  → 徐々に拡散モデルの裁量を拡大。coach-Iの評価が低くても、
    拡散モデルが強く主張する手を通しやすくする。

最終 (Phase 5):
  REJECT = is_illegal_move(action) のみ
  → ルール逸脱（手牌にない牌を切る、リーチ条件不成立 etc.）だけ弾く。
    打牌選択は完全に拡散モデルに委ねる。
```

coach-Iの評価が閾値を超えなくても、拡散モデルの確信度が極端に高い場合は通すなどの条件追加も可能。

**成功基準**: フェーズ2モデルがフェーズ1と同等以上の一致率、かつサンプリングの多様性（同一局面で異なる打牌を生成できる）を示す。

## フェーズ3: マルチアクション拡散（打牌 + リーチ + 鳴き）

**目標**: 打牌だけでなくリーチ判断・鳴き判断も同時に拡散過程で決定する。これにより「打牌A（リーチあり）」と「打牌B（リーチなし）」のトレードオフを確率的にモデル化する。

- [ ] アクション空間の拡張
  - 34打牌 × 2（リーチ有無）+ 鳴き行動（副露種類別）
  - ツモ和了・ロン和了の判断も含める
- [ ] `core/diffusion_policy.py` をマルチヘッド出力に拡張
- [ ] 学習: マルチタスク損失（各アクションタイプごとに重み付け）
- [ ] 評価: 各判断の一致率 + シミュレーション上での期待スコア

## フェーズ4: 条件付き拡散（順位目標 + 他家モデリング）

**目標**: ユーザーの当初アイデア「プロンプト=1〜3位, ネガティブプロンプト=4位」を実装する。

- [ ] 条件付け機構 (Classifier-Free Guidance)
  - 学習時に条件ラベル（最終順位）をドロップアウト
  - 推論時にガイダンススケール `w` で制御
  - `score = w * score_cond + (1-w) * score_uncond`
- [ ] 順位条件ラベル
  - 牌譜の最終結果から各局面に順位ラベルを付与
  - 1位/2位/3位/4位 の4クラス or スカラーの着順確率
- [ ] 他家行動の条件付け
  - opponent_model の出力（危険度, シャンテン推定）を条件として拡散過程に注入
  - 画像生成における「深度マップ」や「セグメンテーションマスク」に相当
- [ ] `core/guidance.py` — Classifier-Free Guidance / Classifier Guidance 実装

**このフェーズで実現すること**:
- 「1位を目指すなら積極的に押す」打牌
- 「4位回避が最優先なら安全志向」の打牌
- 「他家がリーチで攻めてるならベタオリ」へのスムーズな遷移

## フェーズ6: 進化的最適化（Neuroevolution）

**目標**: 教師あり学習（人間模倣）の限界を超え、実際の対戦結果を fitness にした進化的最適化で真の強さを追求する。

**モチベーション**: 教師あり学習は「プロの打ち方」を模倣するが、プロの打ち方が必ずしも雀魂PT最大化に最適とは限らない。実際の対戦結果（PT/順位）を直接最適化することで、coach-Iのルールやプロの常識を超えた打牌を発見できる可能性がある。

### アプローチ

既存の `tools/ga_tune.py` の枠組みを拡散モデルの重み最適化に拡張する：

```
各個体 = 拡散モデルの重みセット（or coach-Iパラメータも込み）

リーグ戦方式:
  1. 個体プールから N 体を選出
  2. 各リーグ (4人一組) で対戦 × 数千試合
  3. 各試合の結果（着順/PT）を記録
  4. 平均PTが高い個体を selection
  5. 重みに crossover + mutation を適用して次世代
  6. 収束するまで繰り返し
```

### 既存インフラの流用

| 既存ツール | 役割 |
|---|---|
| `tools/ga_tune.py` | GAフレームワーク（選択・交叉・突然変異） |
| `tools/manue_battle.py` | 対戦実行バッチ |
| `tools/evaluate_parameter_fitness.py` | 個体評価（平均PT算出） |
| `config/battle_config.json` | 対戦設定（部屋, シード etc.） |

### 既存GAとの違い

| | 現行GA (coach-I) | 拡散モデルGA (diff-I) |
|---|---|---|
| 遺伝子 | ファジィ閾値・重みパラメータ (≈ 50次元) | ニューラルネット重み (≈ 10万次元) |
| 交叉 | パラメータ値のブレンド | 重みのブレンド or レイヤー単位交換 |
| 突然変異 | 微小な値変動 (±0.01) | 重みノイズ付加 (SGD的) |
| 評価 | 数十試合で収束 | 高次元なので数千試合必要 |

### 実装ステップ

- [ ] `tools/train_evolution.py` — 進化学習エントリポイント
  - 拡散モデルの重みを遺伝子としてエンコード/デコード
  - 各世代: 個体生成 → リーグ対戦 → fitness算出 → selection → crossover → mutation
- [ ] リーグ戦バッチの並列化
  - 既存の `manue_battle.py` を拡張し、複数個体を同時に battle させる
  - GPU推論とバトルサーバを非同期パイプライン化
- [ ] Fitness設計
  - 主指標: 平均PT (雀魂準拠: 1位+50, 2位+10, 3位-10, 4位-30)
  - 副指標: 放銃率, 和了率, 平均打点（デバッグ用）
- [ ] 探索と収束のバランス調整
  - mutation rate のスケジューリング
  - エリート保存 + トーナメント選択
- [ ] coach-I GAとのクロスブリード（オプション）
  - 拡散モデルの重み + coach-Iパラメータを同時進化
  - 「ニューラルな直感 × ルールベースの堅牢性」のハイブリッド探索
