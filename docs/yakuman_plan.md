# 役満狙いロジック実装計画

## 概要
人間や強いAIが役満を狙うタイミングを再現し、AIが積極的に役満を狙うロジックを実装する。

## 基本方針
- **評価値**: シャンテン数に二次関数で比例（近いほど高評価）
- **攻撃度**: 役満手は高打点のため攻撃度を引き上げる
- **脅威度**: 他家の役満手を見えてたら点数的脅威が下がるので降りる判断も行う
- **成立不可排除**: 見えてる牌で完全に成立しない役満は絶対に狙わない

## 対象役満（全13種）

| 役満 | 成立条件 | 成立不可能判定 |
|---|---|---|
| 国士無双 | 老頭・字牌13種揃え | 13種全て山に0枚 |
| 四暗刻 | 暗刻4組 | 特定牌が全て見えて暗刻にできない |
| 大三元 | 三元牌（白發中）の刻子3組 | 白/發/中が全て3枚ずつ見えてる |
| 字一色 | 字牌のみで構成 | 「必要な枚数が、残りの枚数足りてるか？」で判定。例：白白白中中中南南南西西東東（テンパイ）→ 西と東がどちらも2枚切れなら枚数足りず成立不可。白白白中中中南南南西西西5s（一向聴）→ 持っていない発・東・北が全部3枚切れなら成立不可 |
| 清老頭 | 老頭牌（1,9）のみで構成 | 老頭牌の合計枚数が手牌枚数を下回る |
| 九蓮宝燈 | 一色の1-9牌（1と9は3枚以上必要＝1面待ちの形） | 1または9が全て4枚見えてる |
| 大四喜 | 風牌（東南西北）の刻子4組 | 風牌の刻子が4組作れない |
| 小四喜 | 風牌の刻子3組＋対子1組 | 風牌の刻子3組が作れない |
| 緑一色 | 緑一色候補牌（23468s白發）のみ | 候補牌の合計枚数が足りない |
| 四槓子 | 槓子4組 | ①山に残ってる牌の種類が4種以下、②手牌の暗刻数が3つ以上で槓にできる対子が1つもない（いずれかを満たしたら成立不可） |
| 天和 | 親の配牌時に和了 | 親でない |
| 人和 | 子の配牌時に和了 | 子でない |

## 評価値設計

```
役満ボーナス = 基本ボーナス × シャンテン補正 × 巡目補正 × 点数必要度補正 × 成立可能性補正
```

### シャンテン補正（二次関数）
**各役満専用のシャンテン数**で計算（通常のシャンテン数ではない）。
```
補正值 = (4 - yakuman_shanten)^2 / 16
```
- テンパイ（0向聴）: 1.0
- 1向聴: 0.5625
- 2向聴: 0.25
- 3向聴: 0.0625
- 4以上: 0

**各役満のシャンテン数計算方法**:
- 国士無双: 老頭・字牌の所持種数（13種 - 所持種数）
- 四暗刻: 暗刻数（4 - 暗刻数）
- 大三元: 三元牌の刻子数（3 - 刻子数）
- 字一色: 字牌以外の牌の枚数
- 清老頭: 老頭牌以外の牌の枚数
- 九蓮宝燈: 一色内の1-9牌の不足枚数
- 大四喜/小四喜: 風牌の刻子数（4 - 刻子数）
- 緑一色: 緑一色候補牌以外の牌の枚数
- 四槓子: 槓子数（4 - 槓子数）

### 巡目補正
- 序盤（1-6巡）: 1.0（十分な時間がある）
- 中盤（7-12巡）: 0.8（ある程度の時間がある）
- 終盤（13巡以降）: 0.5（時間が少ない）

### 点数必要度補正
- トップ目（点差≤0）: 0.5（余裕があるため狙いにくい）
- 点差が指定ライン以下: 0.75（GAで調整可能）
- 点差が指定ライン超: 1.0（逆転に必要）
- **計算式（親子判定で自動選択）**:
  - 子: mangan 10000 / haneman 15000 / baiman 20000 / sanbaiman 30000 / yakuman 40000
  - 親: mangan 16000 / haneman 24000 / baiman 32000 / sanbaiman 48000 / yakuman 64000

### 成立可能性補正
- 完全に不可能: 0（除外）
- 一部不可能: 0.5
- 可能: 1.0

## 攻撃度の上昇

`strategy_manager.py` の `compute_base_attack()` に役満ボーナスを追加：
- 役満進行度が高い場合、攻撃度を最大1.0に引き上げ
- 理由：役満は倍満以上の打点を期待できるため、通常の和了よりも積極的に戦う価値がある

## 他家の脅威度（降り判断）

`strategy_manager.py` の脅威度算出に役満要素を追加。

### 警戒対象の役満（観察可能な範囲）

| 役満 | 警戒ポイント |
|---|---|
| **国士無双** | 中張牌から捨てていて、么九牌がどんどん出てき始めた場合 |
| **四槓子** | カンが4個ある。3個あれば警戒。2個でも手が高そうで怖い |
| **大四喜・小四喜** | 副露で風牌（東南西北）が3種以上その人から見えてる。2種からでも危なげ。責任払いがあるため |
| **大三元** | 三元牌（白發中）が2種副露で見えてる。責任払いがあるため、2種から警戒が必要 |

### 警戒できない役満

- **緑一色**: ホンイツと区別がつかない
- **九蓮宝燈**: 清一色と区別がつかない
- **天和・人和・地和**: 警戒できない

### 脅威度の調整

- 上記の役満警戒に該当する場合、相手の脅威度を引き上げる
- 自分の役満と被る牌が多い場合、相手の脅威度を下げる
- 例：大三元狙いの相手がいて自分の三元牌が被る場合

## ファイル構成

| ファイル | 変更内容 |
|---|---|
| **新規: `core/yakuman_evaluator.py`** | 全役満の進行度計算＋成立可能性判定 |
| **改修: `core/evaluator.py`** | `_hand_value_bonus()` に役満ボーナス追加 |
| **改修: `core/strategy_manager.py`** | `compute_base_attack()` に役満攻撃ブースト、脅威度に役満要素追加 |
| **改修: `config/`** | パラメータ追加 |

## 設定パラメータ

```json
{
  "YAKUMAN_PROGRESS_THRESHOLD": 0.6,
  "YAKUMAN_BONUS_SCALE": 200,
  "YAKUMAN_MIN_SHANTEN": 2,
  "YAKUMAN_ATTACK_BOOST": 0.3,
  "YAKUMAN_THREAT_REDUCTION": 0.2
}
```

## 処理フロー

```
_hand_value_bonus()
  ├─ 既存の染め手・字牌評価
  └─ NEW: yakuman_progress = YakumanEvaluator.evaluate(hand, melds, ...)
       ├─ 各役満の進行度を計算
       ├─ 進行度 × ボーナススケール → 加算スコア
       └─ 記録（record_detail）

compute_base_attack()
  ├─ 既存の攻撃度計算
  └─ NEW: yakuman_boost = YakumanEvaluator.attack_boost(...)
       └─ 役満進行度が高い場合、攻撃度をブースト

compute_opponent_threat()
  ├─ 既存の脅威度計算
  └─ NEW: YakumanEvaluator.threat_reduction(...)
       └─ 他家の役満進行度に応じて脅威度を調整
```

## 実装順序

1. `yakuman_evaluator.py` 作成（進行度計算＋成立可能性判定）
2. `evaluator.py` 改修（役満ボーナス追加）
3. `strategy_manager.py` 改修（攻撃度ブースト＋脅威度調整）
4. `config/` パラメータ追加
5. テスト・調整

## 注意点

- 既存の評価ロジックを壊さないよう、ボーナス加算方式を採用
- 役満進行度は0.0〜1.0の範囲で正規化
- 成立不可能な役満は即座に除外（計算コスト削減）
- パラメータは調整しやすいように外部化
