# 未実装要件

## 捨牌からの情報リーク対策（対々和・染め手時）

### 概要
現在のAIは、各牌の評価値のみで打牌選択を行っており、自分の捨て牌が相手に与える情報を考慮できていない。

### 問題
- 対々和や染め手を狙う際、メインスート以外の牌だけを切っていると、相手に「この人はこの色を待っている」と筒抜けになる
- 結果的に欲しい牌が止められ、和了率が低下する

### 対策案
- 自分の捨て牌に特定の色が偏っている場合、その色以外の手牌に「情報隠蔽ボーナス」を加算する
- 例: 索子ホンイツ狙いで、序盤から萬子・筒子だけを切っている → 索子は「偽装捨て」として一定確率で混ぜる
- 偽装捨ての程度は巡目・押し引き・手の価値に応じて動的に調整

### 優先度
- 高（上位互換AIには必須）
- 現状は基本評価関数のGAチューニングを優先する
- 基本パラメータが固まった後のフェーズ2として実装予定

## 役種別シャンテン数（toitoi・honitsu特化）

### 概要
現在のAIは常に標準手（順子ベース）のシャンテン数のみを使用している。そのため、対々和や染め手など特化した手組に向けた適切な評価ができていない。

### 問題
- 対々和志向の手牌（刻子＋複数の対子）でも標準シャンテン公式では高めに出る
- 例: 1開局+1暗刻+3対子+2孤立 = 麻雀的にはtoitoiで2シャンテンだが、標準公式では5シャンテン
- 結果的にtoitoi志向の打牌選択が過小評価される

### 対策案
- 手牌の構成から役種（toitoi, honitsu, chinitsu, 標準）を推定する
- 各役種に適したシャンテン数を計算し、最も進んでいる方向性を採用する
- toitoi向けシャンテン: 刻子=完成メンツ、対子=1シャンテン(=あと1枚でメンツ)、孤立=2シャンテンとして計算
  - 例: 1開局+1暗刻(2メンツ)+3対子+2孤立 → 残り必要メンツ数2、対子3つあるので最善2シャンテン

### 優先度
- 最優先（シャンテン数が正確でないと全評価が狂う）
- 別セッションでデバッグ・実裝予定

## 壁スジ逆手戦術（待ち牌としての価値評価）

### 概要
壁スジの牌は相手に「安全牌」と認識され、切りやすい。この性質を利用して、あえて壁スジの牌を待ち牌として残す戦術がある。

### 問題
- 現在のAIは壁スジを防御的に評価するのみで、「相手が切りやすい＝和了しやすい」という攻めの視点がない
- 例: 8sが4枚見え（壁）で5sが壁スジ → AIは5sを「安全なキープ牌」と評価するが、上級者は5sを「通りやすい待ち」として狙う

### 対策案
- 壁スジの牌を待ちとして持つ場合、和了率補正を加算する
- 特に押し（攻め）モード時は壁スジ待ちの価値を高く評価する

### 優先度
- 低（GAチューニングで自然に獲得される可能性が高い）
- 基本パラメータ最適化後に効果を検証
